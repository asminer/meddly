cnstr_model:

    New model for constraint problems!

    Stuff we should allow:

        constraints of the form x_i >< x_j + delta
            for any comparison ><:
                ==, !=, <, <=, >, >=

        constraints of the form x_i == a_1 OR a_j == a_2 OR ...
            (allowing the same variable twice)
            (allow arbitrary comparisons?)

        user-defined on a pair of variables x_i, x_j:
            provides function f, where f(x_i, x_j) is true/false

        linear sum
                x_i + x_j + x_k + ... >< c
            for any comparison ><:
                ==, !=, <, <=, >, >=

        weighted linear sum
                a_i x_i + a_j x_j + a_k x_k + ...  >< c
            for any comparison ><:
                ==, !=, <, <=, >, >=
            this subsumes x_i >< x_j + delta


        OR of a list of constraints

        AND of a list of constraints



    current models and what they use

        nqueens:
            x_i != x_j
            x_i != x_j + d
            x_i != x_j - d

        queen cover (for each square, is there a queen):
            is there a queen in a given row/col/diag
            OR( qin_i, qin_j, qin_k )
            could use also
            MAX( qin_i, qin_j, qin_k ) == 1
            or
            qin_i + qin_j + qik_k > 0

            exactly Q queens:
            (qin_1 + qin_2 + ...) == Q


        qc2 (for each queen, where is it):
            is there a queen in a given row/col/diag
                qpos1 == a1 or qpos1 == a2 or ... or
                qpos2 == a1 or qpos2 == a2 or ... or
                qpos3 == a1 or qpos3 == a2 or ...
            could make one huge list of positions and ask if any queen
            is there, to determine if a square is being attacked

        life (reverse):
            (n1+n2+...+n9) == 3     if this square needs to be alive
            (n1+n2+...+n9) != 3     if this square needs to be dead

        knight's tour (for each square, when to visit it):
            a==16 OR
            ( a==b1-1 AND a!=b2-1 AND a!=b3-1 ) OR
            ( a!=b1-1 AND a==b2-1 AND a!=b3-1 ) OR
            ( a!=b1-1 AND a!=b2-1 AND a==b3-1 )

        knight's tour (for each visit, which square):
            loc_i+1 == a and (loc_i == b1 or loc_i == b2 or ...)
            or ...

            to encode loc_i+1 is reachable from loc_i
                reachable(loc_i+1, loc_i): user-defined function

            if we do row, col positions then maybe:
                row_i+1 - row_i == 1  AND  col_i+1 - col_i == 2
            OR
                row_i+1 - row_i == 1  AND  col_i+1 - col_i == -2
            OR ...

            unique positions (easier to not use row/col):
                we sometime visited position p:
                    loc_1 == p or loc_2 == p or ...

    * updated node, CT storage using long instead of int for node handles.

    * new byte-based node storage
        first and last byte: storage type
            0: small hole (less than 256 bytes)
            1: large hole (more than 256 bytes)

            2..: specifies which codec to use for node storage

            codecs are registered but otherwise agnostic to node storage.
            codec table keeps track of
                constants a and b, the number of bytes for a node
                is a * size + b. If a==0 then we don't need to store a size.


            examples:
            BDD, d-byte down, e-byte EV
                a = 0, b = 2*d + e  (assuming normalized)

                use d in { 2, 4, 6 } and e in { 1, 2, 4, 8 }.
                (e = 1 for REXBDDs)

            12 combos


            truncated full storage, s-byte size, d-byte down, e-byte EV
                a = d+e, b = s

                use s in { 1, 2, 3 },
                    d in { 2, 4, 6 },
                    e in { 2, 4, 8 }.

            27 combos

            sparse storage, s-byte size and index, d-byte down, e-byte EV
                a = s+d+e, b = s

                use s in { 1, 2, 3 },
                    d in { 2, 4, 6 },
                    e in { 2, 4, 8 }.

            27 combos


            AND/OR nodes, b-byte size, a-byte down

                use b in { 1, 2 },
                    a in { 2, 4, 6 }

            6 combos


            implicit nodes, d-byte low, high, delta (signed)
                a = 0, b = 3d

                use d in { 1, 2, 4 }

            3 combos
